## What

WP-902's row of §12 asks for "one package per target below its gate (`WP-902a`, `WP-902b`, …)" and
takes one check: "COV-2 holds". WP-902 is retired and replaced by four parts, one per production
target that holds a file below 97.5 % of its lines on the measurement of 2026-11-22, lettered in the
order of the targets of §4.2 without a gap:

| Part | Target | Why it is a part |
|---|---|---|
| WP-902a | `CZTronDSP` | `ztd_thread.c` at 96.88 % (62 of 64 lines) |
| WP-902b | `ZTronDSPDesign` | five files below 97.5 % (91.94 % to 97.33 %) |
| WP-902c | `ZTronDSPAnalysis` | `ConstantQ/ConstantQProjection.swift` at 96.15 % (50 of 52 lines) |
| WP-902d | `ZTronDSPUI` | `Pinch/PinchGestureModifier.swift` at 92.86 % (104 of 112 lines) |

`ZTronDSPCore`, `ZTronDSPMetal`, `ZTronDSPIO` and the facade `ZTronDSP` get no part: every target is
at 95 % or more, and these four hold no file below 97.5 % (the facade holds no executable line).

## Why

The rule of the brief: one part per target that is below 95 %, or that holds a file below 97.5 %
(COV-3 is asked of every file by the verifiers), lettered in the order of §4.2, letters not skipped.
No target is below 95 %, so the second condition alone decides.

## Evidence

One instrumented run of every test target in Debug on the simulator `ztdsp-27` (iOS 27.0), 2026-11-22
04:00–04:04, `-enableCodeCoverage YES`, read with `xccov` by `Scripts/coverage-gate.sh` (2 118 tests
passed): aggregate 99.55 % (25 716 of 25 833 lines); `CZTronDSP` 99.70 %, `ZTronDSPCore` 99.69 %,
`ZTronDSPDesign` 98.70 %, `ZTronDSPMetal` 100.00 %, `ZTronDSPAnalysis` 99.85 %, `ZTronDSPIO` 99.48 %,
`ZTronDSPUI` 99.64 %. The per-file table is in `Docs/Process/reports/impl-WP-902a.md`.

## Sections affected

§12, the row of WP-902 (retired, §11.3); the ledger (§11.9). The rules of §10.2 are unchanged.

Outside the specification: the self-test of the process files (`Scripts/tests/test-process-files.sh`,
WP-008) counted every row of the ledger as one of the 289 packages of §12, so the four rows of the parts
made it fail ("it has one row for each of the 289 packages (293 rows)"). It now leaves out the rows of a
split's parts, those directly under a `Retired` row, which `Scripts/ledger.sh --check` already vouches
for (`Scripts/lib/ledger.py` accepts a part that §12 does not list only under its retired package). If
§12 is edited to list the parts in the place of WP-902, the test's 289 changes with it.

## For a split (§11.7)

The original row has one acceptance check, "COV-2 holds". It is taken, unchanged, by the last part,
which runs the gate on a fresh instrumented run after the other parts. Each part also takes the
per-file closure of its target that the brief asks for (COV-3 as the verifiers will apply it).

| Part | Acceptance checks it takes | Lenses |
|---|---|---|
| WP-902a | Every file of `CZTronDSP` at 97.5 % or more, or named with its reason (ledger backlog, finding id, or a `// coverage:ignore(<reason>)` mark of COV-4 b) | T, A |
| WP-902b | Every file of `ZTronDSPDesign` at 97.5 % or more, or named with its reason | T, A |
| WP-902c | Every file of `ZTronDSPAnalysis` at 97.5 % or more, or named with its reason | T, A |
| WP-902d | Every file of `ZTronDSPUI` at 97.5 % or more, or named with its reason; and WP-902's check, unchanged: **COV-2 holds** (aggregate ≥ 97.5 %, each target ≥ 95 %) | T, A |

Whatever depended on WP-902 depends on all four parts (§11.7). In §12 only WP-906 names it, through
"all".
