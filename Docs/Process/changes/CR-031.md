## What

WP-901a compared every type, protocol, function and member that §4–§8 and Appendix A write out with the digests of `Docs/API`, section by section (`Docs/Process/reports/impl-WP-901a-909.md`, the comparison table). Every name the specification writes is public, with the labels it gives, except the four below. Each one that an existing change request already covers is left there; these are the ones that no change request names.

1. **`PipelineStage` is split in two.** §5.11.1 declares one protocol: `public protocol PipelineStage: Hashable, Sendable` with `Input`, `Output` and `lower(_:)`. The code declares `StageValue: Hashable, Sendable`, which holds `lower(_:)` with `stageName`, `activation`, `parameters` and `replacingParameters(_:)` (the last four with defaults: §5.9, ANI-2, WP-305), and `PipelineStage: StageValue`, which adds `Input`, `Output` and `stageDescriptions`. `SequenceStage` (§5.11.1, "A sample-domain stage in C") refines `StageValue` too, and a context-dependent family adopts `StageValue` alone (ORD-1), because neither names one input and one output domain. A stage written outside the package is spelt as §5.11.1 shows: it conforms to `PipelineStage`, names `Input` and `Output` and implements `lower(_:)`. CR-015 item 11 lists `StageValue` among the additions; it does not say that `lower(_:)` moved there. **Proposed wording** of the block in §5.11.1:

   ```swift
   public protocol StageValue: Hashable, Sendable {
       func lower(_ context: inout LoweringContext) throws(DSPError)    // control context: emit kernels or one node
   }
   public protocol PipelineStage: StageValue {
       associatedtype Input: SignalDomain
       associatedtype Output: SignalDomain
   }
   public protocol SequenceStage: StageValue {}                         // any sampled sequence, domain kept
   ```

2. **`MicrophoneAuthorizing` is internal.** §4.6 and COV-5 name it as a seam beside `AudioSessionControlling` and do not say whether an app sees it. `AudioSessionControlling` is public because `AudioSessionPolicy.custom(_:)` (§4.6) hands one to the app's closure. Nothing public takes or returns a `MicrophoneAuthorizing`: the public initialiser of `HardwareInputSource` builds the source with `SystemMicrophoneAuthorizer`, and the tests inject a fake through `@testable import` (COV-5 holds). **Proposed:** §4.6 says the seam is internal, as §4.4 says of `SourceAdapter` ("Internally a `SourceAdapter` …").

3. **`FrameScheduler` is internal.** §8.3 describes "a `FrameScheduler` (a `CADisplayLink` wrapper)" and WP-802 tests it with a fake clock. Each view owns one: the surface coordinator and the axis watcher create it with a `DisplayLinkClock`, and an app neither makes one nor sees one. **Proposed:** §8.3 says the scheduler belongs to the views ("each view schedules its draws with a `FrameScheduler` of its own, internal to `ZTronDSPUI`").

4. **Two optional strategy values are absent: `FFTBackend.mpsGraph` and `MedianStrategy.incrementalSortedLanes`.** The catalogue of §5.3 marks both optional, with their packages (WP-613, WP-533), and both packages are `Awaiting-trigger` in the ledger. **Proposed:** no change to the text; the values arrive with their packages. Recorded so that every name §4–§8 writes and the digests do not hold has a place.

## Why

The map of `Docs/API/spec-map.tsv` lists every public symbol at the clause that names it; WP-901a.4 asks that what the specification names and the code does not provide as written is implemented or carried by a change request. Items 1 to 3 are the implementation's choices and keep the public surface smaller or the extension spelling unchanged; item 4 is the plan's own option.
