## What

1. **A push source cannot say that it is not real time.** §4.4 gives `pacing` to pull sources only, and §5.4 says `isRealTime` is false for `.asFastAsPossible` sources. `FileSource` is a push source with a pacing of its own. As built, the engine serves every push source on the analysis thread and reports `isRealTime == true`, so a file read as fast as the consumer drains is processed on the real-time thread beside a microphone. Proposed: `PushSampleSource` gains `var pacing: Pacing { get }` with a default of `.realTime`; a push source that answers `.asFastAsPossible` gets a utility thread of its own and `isRealTime == false`, as a pull source does. This changes a protocol of §4.4 (SRC-1), so it waits for the owner.
2. **`.external` changes nothing**, so an `input:` given with it must already be the input the session records from (otherwise `sourceUnavailable`), and `dataSource:` is left to the app.
3. **`.custom`** runs its closure at every `prepare()`. The option modifiers (`mixingWithOthers()` and the Bluetooth ones) do not apply to it; activation and `deactivatingOnStop()` do.
4. **CAP-3 before CAP-5.** A session that is left untouched also gets no haptics call. When the package sets the category, a refusal of that call is logged and is not an error.
5. **Bluetooth inputs are filtered by the policy** even when the app's own session already routes hands-free.
6. **CAP-8, third row, against the state table of §4.5.** `start()` has no effect on an interrupted session, so "stays stopped until the host calls `start()`" is `stop()` then `start()`. The documentation of the source says so.
7. **Before iOS 16 a suspended app** is told that an interruption began because it was suspended, and is never told that it ended. The source treats that notice as an interruption and its end in one step.
8. **A route change that leaves the format as it was** leaves a running capture engine alone.
9. **The tap**: the pacer looks once per block duration; the pacing buffer holds 1.5 s; the source replaces a tap already on the bus; a change of the node's format is `.formatChanged`.
10. **The file**: `stop()` then `start()` continues where the pipeline left off (exactly without rate conversion, at the nearest file frame with it); `stop()` waits at most five seconds for a reader that is stuck in a read.
11. **`ztd_sink_node.h` names `AudioBufferList`, `AudioTimeStamp` and `AVAudioSinkNode` as incomplete types** and does not import AVFAudio, so that CoreAudioTypes' `AudioBuffer` does not reach every file that imports the core (which has an `AudioBuffer` of its own). The digest shows the parameter as an opaque pointer.
12. **PLAT-1 has no row for two deprecations of iOS 27**: `connect(_:to:format:)` (the error-returning `connectNode` is used where it exists) and the interruption notification (the classic one is used on every OS).
13. **AVFAudio raises an Objective-C exception**, which Swift cannot catch, when an engine with neither an input nor an output node is prepared or started. The capture adapter names the input node first and checks the format before it connects. There is no general exception barrier; one would be an Objective-C shim in `CZTronDSP`.
14. **COV-5 asks for adapters without branches.** They hold the availability gates of PLAT-1 and three guards (item 13, a refusal of voice processing, a converter error).
15. **Additions to the public surface** beyond §4.6: none in `ZTronDSPIO`. In `CZTronDSP`: `ztd_sink_tap_create/retain/release/set_ring/receive/written_frames/discarded_frames`, `ZTD_SINK_TAP_MAX_CHANNELS`, and for Objective-C `ztd_sink_node_has_realtime_safe_initialiser`, `ztd_sink_node_receiver`, `ztd_sink_node_create`.

## Why

Item 1 is a gap between two sections. The rest are choices the specification leaves to the implementation, or behaviour of the system found while building.

## Evidence

`ZTronDSPIOTests`: 134 tests in 13 suites; `CZTronDSPTests`: 202 tests in 28 suites (13 for the sink node); Debug and Release on the simulator. The simulator tests run the real audio session, a real `AVAudioEngine` and the real sink node with both initialisers, with only the permission seam replaced: the test host of a package has no identity the system can grant the microphone to.

## Not done, and why

- Every device run: WP-708's device lab, real hot-plug, Bluetooth, the data sources of a built-in microphone, iOS 15 to 26 at run time. The classic initialiser, the classic tap and the classic connect were run on iOS 27 by forcing them.
- The simulator's session accepts what a device refuses (it took ambient with voice chat, and a deactivation under a running engine), so refusals of `setActive`, of the haptics call and of a preferred input are untested.
