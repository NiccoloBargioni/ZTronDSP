## What

1. **`Animatable` sits on an internal host view, not on the public components.** The appearance values live in the SwiftUI environment; a public `animatableData` on `SpectrogramView` and its siblings would be a public setter (IMM-2) with a row in `mutable-by-design.md`. ANI-1 is met through the internal `SurfaceHost`.
2. **`.frequencyRange` is in the unit of the feed's axis**: hertz for a spectrogram, beats per minute for a tempogram, seconds for lags and quefrencies, rows otherwise.
3. **The row-axis views share one implementation** and take their labels from the feed's `FeedAxis`. `PitchClassAxisView` shows the twelve names before the feed has an axis.
4. **`DSPAxis`** (`.frequency`, `.time`, `.pitchClass`, `.tempo`) is the argument of `.axis(_:)`; the specification names the modifier, not the type.
5. **`.dspEnvironment(_:)` takes an optional session** and publishes the reference environment (48 kHz, one channel, no latency) without one. Only the four keys of ENV-4 are public (`dspSampleRate`, `dspNyquistFrequency`, `dspChannelCount`, `dspLatency`), read-only.
6. **The waveform's fill follows the colour scheme** (black on light, white on dark): the specification has no colour modifier for it.
7. **The legacy pinch path** (before iOS 17) decides its axis after 8 points of travel of the first finger and counts the scale from that moment, so nothing jumps.
8. **Size transitions.** A plain resize reported by the size probe is a transition of one tick, presented with the transaction, and is not followed by a spare draw. A draw that finds no drawable is tried on two more ticks, then waits for the next cause.
9. **PINCH-4 is not met on a time axis that is not live.** A pinch along time is anchored at the newest column: the renderers have no time offset. Wanted from `ZTronDSPMetal`: `HeatmapRenderer.setVisibleColumns(_ columns: Double?, endingAt newest: Double?)` and the same for the waveform renderer's pairs.
10. **Errors of `.pipeline(_:on:)`** (a pipeline that does not compile, a sink in use) are logged (`os.Logger`, subsystem `com.zombietron.ztrondsp`, category `pipeline-host`) and the earlier pipeline keeps running. The specification gives the modifier no way to hand an error to the view. The owner decides whether it should.
11. **A component is not presented while `\.scenePhase` is not `.active`.** In a bare hosting controller inside the test process the phase reads `.background`, so the hosted tests inject it; to be checked in an application.
12. **The assumption of §8.7 is confirmed** on the iOS 27.0 simulator: a view that is `Animatable` over a vector whose length is known at run time receives one interpolated value per display frame inside `withAnimation` (about 30 updates in half a second, no re-plan). The fall-back was not built.
13. **WP-819 and WP-823 rest on assumptions their spikes have not confirmed** (WP-818, WP-822 need the Examples project): the table of PINCH-8 and the detection rule of SZ-4. The lines that would change: in `Pinch/PinchGestureModifier.swift` the three gesture builders and `PinchPath.current`; in `Pinch/PinchTracker.swift` the `.magnification` and `.legacy` cases with `decisionDistance`; in `Surface/SurfaceCoordinator.swift` `stepSizeTransition()`, `reportSize` and the transaction branch of `render(to:presenting:)`; `LayerGeometry.isMoving` and `MetalLayerAdapter.geometry` in `Surface/MetalSurface.swift`; the size lanes of `SurfaceHost.animatableData`. What was seen in the test process: a SwiftUI frame animation steps the model bounds once per display frame (presentation equals model, no animation keys); a UIKit-animated change of the host's bounds snapped the hosted Metal view; a rotation could not be observed.
14. **What SwiftUI does on iOS 27, and how the views are built around it** (V-4, "no per-frame invalidation"): a child's body is skipped only when its stored bytes are identical; `Equatable` conformance and `.equatable()` are not consulted; a view that reads an environment key whose default value is computed is evaluated again with every ancestor. Hence stored default values, a plain option set for the axes shown, and reference-backed axis drawings.
15. **Wanted from `ZTronDSPCore`**: a notification that a feed's shape changed (axis, column rate, history), for example `onShapeChange(_:) -> FeedObservation` on `HeatmapFeed` and `WaveformFeed`. Without it the axis views look at the feed when its liveness changes and twice a second while it is live.
16. **Found in `ZTronDSPCore`, given to the engine's fix cycle**: a value update that brings a gain to exactly 0 dB, or away from it, clears the feed of the branch behind the gain and withholds about thirty blocks; a running session installs a new plan only when blocks flow.
17. **Additions to the public surface** the specification does not name: `DSPAxis`; the two bound forms `valueRange(_: Binding<…>)`, `frequencyRange(_: Binding<…>)`, `timeSpan(_: Binding<Double>)`, `amplitudeRange(_: Binding<…>)` are those of VC-4.

## Why

Items 9, 15 and 16 need API or fixes outside the target. Items 12 and 13 record what §8.7, PINCH-8 and SZ-4 ask to be recorded. The rest are choices the specification leaves to the implementation.

## Evidence

`ZTronDSPUITests`: 179 tests in 14 suites; three runs in Debug and three in Release in the main tree on 2026-11-16, no failure. The implementer's 26 mutation checks were all caught. Line coverage of `Sources/ZTronDSPUI` as the implementer measured it: 98.69 %; the lines never run are the gesture closures of the iOS 17 and legacy paths in `Pinch/PinchGestureModifier.swift`, which need real touches.
