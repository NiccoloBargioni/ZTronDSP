## What

The value type `Window`, its vDSP and package shapes, custom windows and `samples(count:)` are in `ZTronDSPCore/Toolkit`. `WindowAnalysis` and `window.analysis(frame:hop:)` stay in `ZTronDSPAnalysis`.

## Why

§5.11.4 lists `Window.samples(count:)` beside the Analysis-only `FFTBackend` plans, and WP-423 (the windowed-sinc FIR, in `ZTronDSPDesign`) depends on WP-501b. Design cannot import Analysis (DEP-1), so a window that both a filter design and an STFT use has to sit at or below Design. It is a description and a table of samples, not a processing stage, so EXT-1 is kept.

## Evidence

`WindowTests`: the vDSP set bit for bit against the vDSP calls (full, half, symmetric), the package set against `scipy.signal.windows` within 1e-12 (`Tests/Golden/generators/windows.py`), custom windows and WIN-3.

## Sections affected

§4.2 (target table), §5.11.4, §6.4.2.
