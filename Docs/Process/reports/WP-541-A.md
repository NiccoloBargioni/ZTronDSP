## Lens checklist (§11.5)

- **R — real-time safety and performance.**
  - **RT-1.** Not exercised: the source is a pull source, and no I/O thread runs. The pipeline has no stage on the I/O thread.
  - **RT-2.** The heap is counted on the audited thread:
    - 0 allocations over 10 000 blocks and over 300 blocks of the analysis thread;
    - 0 from block 0 (e20).

    Locks, Objective-C messages, logging and `await` are covered by lint RT-7.4, which is clean in `Kernels/`, `Nodes/` and `Engine/Run/`. Dynamic dispatch happens once per entry per block, through the plan's table of function pointers (`Sources/CZTronDSP/ztd_plan.c:282–303`), read.
  - **RT-3.** Nothing is allocated on the plan's thread from the first block on (e20), so every buffer and every setup of the plan exists before the first block runs. The release at retirement was not observed: the audit closes before `detach`.
  - **RT-4.** The outputs cross threads through the feeds' column stores (`HeatmapFeed`) and the latest-value slot of the centroid's binding, by reading.
  - **RT-5.** A copy on write would allocate, and none of the windows allocates. The nodes of the batch hold their state in `AlignedBuffer` or raw pointers, by reading.
  - **RT-6.** Belongs to each kernel's package. As an example, the history ring of the separation flushes what it takes in (`Sources/CZTronDSP/ztd_history.c:45`), read.
  - **RT-7.** Layer 3, for the stock pipeline, is what this package delivers. RT-7.3 names `expectNoAllocations { }`, which counts the caller's own thread. The plan runs on the engine's thread, so the test opens the same counter there through a `ThreadAllocationAudit` (`Sources/ZTronDSPTesting/AllocationAudit.swift:120–184`, `ztdt_alloc_audit_begin`/`end`, the audited thread only). CR-023 item 15 records the method, and M8 shows that it sees one allocation per block in a node. Layers 1, 2 and 4 are the gates of the build.
  - **RT-8.** A pull source drops nothing, and no `.overrun` is asserted (`:165`). A hardware source is outside this package.
  - **RT-9.** Belongs to the engine. The paced test runs on the analysis thread that the engine creates.
  - **The allocation audit exists and passes.** Yes, in both tests and in every run.
  - **No hidden copies.** None: any copy would have allocated in one of the windows.
  - **Complexity.** The complexity of §7.2 belongs to the packages of the stages. The cost of the whole is measured: 143 µs per block in Release.
  - **A benchmark is recorded.** Yes (PERF-1).
  - **Setups.** They are created when the plan is compiled only: e20 audits from block 0 and finds no allocation.
  - **SEL-3.** The median lanes bind their exchange function when the filter is made (`Nodes/MedianKernels.swift:60–62`), read. No per-block choice shows in the audit.
