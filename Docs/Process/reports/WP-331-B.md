## Lens checklist (§11.5)

- **A — API, architecture, platform.**
  - Shapes: `PipelineSession.syncBindings()` is `@MainActor public func`, as §4.5 prints it. The pump is `internal` and `@MainActor` (VIS-1: "binding pump: internal"); the liveness board is internal and lock-guarded.
  - BIND-1: a binding is read in `BoundSwitch.read()` (`@MainActor`) and nowhere else; the plan is compiled off the main thread with the values read there (BIND-4); a re-plan after a format change reuses the positions last seen instead of reading. Verified at run time (above).
  - BIND-2: one `CFRunLoopObserver` on the main run loop, before waiting, common modes, present exactly while the session runs and has a bound switch or result; no timer for switches.
  - BIND-5: no code path writes a `Binding<Bool>`. BIND-6: `capture` replaces what was captured, `release` empties it on detach.
  - BIND-7 / DEP-1: `Binding` is named in `Bindings/` only, through `import struct SwiftUI.Binding`; the one other occurrence is inside the text of a diagnostic. Lint part 3 clean.
  - §9.2: the data plane sees switches only as commands in an SPSC queue whose one producer is the main thread; no actor, no `Task`, no `await` in `Engine/Run/`. §9.5: no Combine, no `AnyView`.
  - `@unchecked Sendable`: `RunLoopHooks`, with its contract at the declaration and its row in the register.
