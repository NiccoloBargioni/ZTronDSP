## Lens checklist (§11.5)

- **R — real-time safety and performance.**
  - `process`, `command` and `reset` are `ZTD_NONBLOCKING`, defined in a target built with function-effect errors (the check bites: `malloc(16)` written into `ztd_gain_process` stops the package build: "function with 'nonblocking' attribute must not call non-'nonblocking' function 'malloc' [-Werror,-Wfunction-effects]"). Read against RT-2: no allocation, no lock, no system call, no logging; every loop is bounded by the frames, the channels or a size fixed at creation.
  - The audit bites: with an allocation the compiler cannot see (a call, from the hot function, to a helper in another file that does `malloc` and `free` and is declared `nonblocking`, as an allow-list entry is; tried in Debug and in Release, with the same counts) in `ztd_biquad_double_process` and `ztd_biquad_double_command` it reports 1 050 allocations.
  - Coefficients and state are allocated in `ztd_biquad_double_create`; no setup. The exchange is a `memcpy` of 5·sections doubles in `command` (ztd_biquad_double.c:55-59), applied between blocks; the state is not touched.
  - Cost O(sections) per sample: the scalar recurrence, three statements per section. Benchmark recorded: `kernel.biquad-double.4-sections.512` 4894 ns (2.4 ns per sample per section; `vDSP_biquad` in single precision: 1923 ns).
  - No size-bound choice in this kernel (one implementation).
