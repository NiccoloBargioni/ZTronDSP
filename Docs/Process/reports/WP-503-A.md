## Lens checklist (§11.5)

- **R — real-time safety and performance.**

- RT-1…RT-9, read for everything the analysis thread runs. `append`, `store`, `frame`, `advance` and `reset` (`Framer.swift:105–178`) contain:
  - no allocation, no lock, no system call and no logging;
  - no `await` and no closure;
  - `memcpy`, the C ring's write, peek and consume (WP-203), and one loop bounded by half a frame (the centred start).
- Creation and release are on the control context, as documented (`:24–26`). The class is not `Sendable`.
- Allocation audit:
  - `FramerTests.framingDoesNotAllocate` exists and passes in Debug and Release;
  - it fails when an allocation is added to `append`: 4 issues, "found 1000 allocation(s) of 40000 byte(s)" (`VerifierA/mutations.py` group M1);
  - with the same change, the audits of the steps built on it fail too (`MelTests`, `SpectralCentroidTests`, `CepstrumTests`, `ValueStepTests`);
  - restored, byte for byte.
- No hidden copies:
  - each sample is written to the ring once;
  - the centred start copies the first half frame once, for the reflection;
  - the fall-back, used only where the system refuses the mirror, copies each sample twice, as documented (`Framer.swift:9–11`); §7.2 row 2 registers a copy as the alternative ("Copy on wrap").
- Complexity as registered in §7.2 row 2: a window is a contiguous view, no copy per hop.
- Setups: none.
- SEL-3: the storage is chosen once, at creation, by what the system grants, not by size. The `if let ring` branch on each call follows that choice.
- Benchmark: see A-14.
