## Lens checklist (§11.5)

- **R — real-time safety and performance.**
  - RT-2, by reading everything that runs on the analysis thread: `CepstrumNode.process` (`Nodes/CepstrumNodes.swift:39-107`), per frame: the bins to double precision (`vDSP_vspdp` ×2), |X|² (`vDSP_zvmagsD`), the floor (`vDSP_vthrD`), `vvlog`, the halving for the real kind (`vDSP_vsmulD`), the phase cleared (`AlignedBuffer.clear`, one `memset`), the double inverse transform (`DoubleDFT.inverse`, WP-502), the square for the power kind (`vDSP_vsqD`), back to single precision (`vDSP_vdpsp`) and one emission. No allocation, lock, system call, Objective-C message, logging or `await`; the sizes passed to vForce are stack values.
  - The audit and the line changed: `theNodesRunWithoutAllocating` passes in Debug and Release. A 64-byte allocation in `CepstrumNode.process`, before the first conversion (before `CepstrumNodes.swift:45`, gate `a509` of `VerifierB/mutations.py`), makes it fail at `CepstrumTests.swift:327`: 3 000 allocations, one per frame of the three cepstrum nodes. Restored, it passes and the tree equals the pristine copy byte for byte.
  - RT-3: the double transform (its setups) and five double buffers are made in the initialiser (`:26-37`), inside the step's factory (`Steps/Cepstrum.swift:125-130`), which the plan compiler runs; the transform length is checked when the step is lowered (`:111-117`).
  - RT-5: `AlignedBuffer` throughout. RT-6: the node keeps no state between frames (`reset` is empty).
  - No hidden copies: the conversions to double and back are the precision the cepstrum is computed in (§6.1, the note at `:4-5`); no closure, no copy-on-write; the transform is a final class held by the node.
  - Complexity (§7.2 row 19): the spectrum comes from the `STFT`, so the node computes the logarithm, O(N), and one inverse DFT, O(N log N), as registered.
  - SEL-3: the arithmetic is double precision, for which §7.4 registers no second implementation; the transform is bound to its length when the plan is compiled.
  - A benchmark is recorded: none (finding 1).
