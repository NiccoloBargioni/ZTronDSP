## Lens checklist (§11.5)

- **A — API, architecture, platform.**
  - Names and shapes (§6.3.4): the order is given as `rollOff: RollOff` with `rounding: RollOffRounding = .exact()` (IIRDesign.swift:104-109), the Core types of WP-103; `.exact()` defaults to `relativeTolerance: 0.02` (Core RollOff.swift:7), as §6.3.4 states. The initialiser reduces to the one by order (`try rollOff.order(rounding:)`), so a design by roll-off *is* the design by the order it names (asserted in `aSlopeIsAWholeNumberOfOrders`). One order is `RollOff.decibelsPerOctavePerOrder` = 20·log₁₀2 (Core RollOff.swift:39). CR-014 item 3 (the ±0.5 dB holds against n·6.0206 dB, not against the rounded figure) describes the tests, which use `n·perOrder`.
  - The semantics of the table are stated where a caller reads them: the initialiser's doc lists the six IIR rows of the table (IIRDesign.swift:81-103; the `BandBoost` and FIR rows belong to WP-421 and WP-424); each family's doc says whether its roll-off is exact (all-pole) or nominal (Chebyshev II, elliptic), as §6.3.4 requires ("The documentation of both families says so").
  - API-6: plain arguments, no configuration object. Typed `throws(DSPError)`; the error for a slope that is not a whole number of orders is `invalidParameter` naming `rollOff`. IMM, `Sendable`: the same value type as WP-418a.
  - VIS-2: 0 findings in IIRDesign.swift and FilterFamily.swift. DEP-1, EXT-1, PLAT-1: as for WP-418a; no UIKit, Combine or `AnyView`.
