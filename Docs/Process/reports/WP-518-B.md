## Lens checklist (§11.5)

- **R — real-time safety and performance.**
  - What of the package runs on the analysis thread: nothing. `ConstantQKernel` is built in `MultirateSparseKernelStrategy.makeNode` on the control context (its type comment: "creating it allocates and transforms, and is not for the analysis thread"); what the analysis thread reads of it is copied, when the node is made, into the four `AlignedBuffer`s of `SparseKernelProduct` (`Nodes/ConstantQNodes.swift:27-47`: row starts and columns as `Int32`, real and imaginary parts apart, E-11), which WP-520 owns.
  - RT-2, RT-3: the kernel, its transform and its thinning are made when the plan is compiled (`ConstantQStrategy.swift:121`, `makeNode`), never per block; nothing of `ConstantQKernel.swift` is called from `process`. RT-5: the kernel's `[Float]`/`[Int]` arrays are read only off the analysis thread; the hot path reads `AlignedBuffer`s. RT-1, RT-4, RT-6, RT-8, RT-9: not applicable (no I/O-thread code, no crossing state, no recursive state, no source, no thread).
  - Allocation audit: what the analysis thread does with the kernel is audited by `ConstantQKernelTests/theProductRunsWithoutAllocating()` (1 000 products of a kernel of this package, after 8 warm-up blocks, inside `expectNoAllocationsRunning`): passes in Debug (runs 1, 2) and Release (run 4); with an allocation added at `ConstantQNodes.swift:57` (injection 11) it fails — the product audit reports the allocation (`ConstantQKernelTests.swift:319`), and so do the node audits that run the product (`ConstantQTests.swift:383`, `:388`, `ChromaTests.swift:301`): 4 issues (`mut-11.log`).
  - Complexity (§7.2 row 13, §7.5 row 13): the kernel is thinned by the energy criterion, a row keeps ≥ 99.9 % of its energy (above), and the tests hold it sparse: fewer than 1/8 of the dense entries in every golden case (`ConstantQKernelTests.swift:79`), at least five entries a row for a Hann atom (`:165`); so the product of WP-520 is O(entries) per octave frame, not O(rows × bins).
  - Setups at compile time and SEL-3: the kernel is made once per node (one kernel for all octaves when `gamma` is 0: `withoutGammaEveryOctaveSharesOneKernel`); there is one implementation of the product, so there is no size choice to bind. Benchmark: not asked by this row (WP-520's).
  - Currency (ALG): `Docs/Numerics/constant-q-kernel.md` opens with the currency check of 2026-11-15 and points to `currency-2026-11.md` row 13, which records "Current" with one more alternative to register (CR-020 item 3). The record is consistent; no network was available to check the literature itself.
