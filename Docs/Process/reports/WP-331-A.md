**Finding 1, to reproduce or resolve.** Probe (fails in Debug and Release):

```swift
final class Token: @unchecked Sendable {}
let rig = Rig(); weak var captured: Token?
let session: PipelineSession
do {
    let token = Token(); captured = token
    let binding = Binding<Bool>(get: { _ = token; return true }, set: { _ in })
    session = try await rig.engine.attach(Pipeline { TestGain(0.5, isActive: binding) }, to: rig.source)
}
try session.start(); await rig.drain()
session.detach(); await rig.drain(); await rig.drain()
#expect(captured == nil)            // fails for as long as `session` is alive
withExtendedLifetime(session) {}
```

With `try await session.update(<an equal pipeline that holds another binding>)` in place of `detach()` the first binding
also stays alive; with an update of other values or of another topology it is released. Cause: `detachNow`
(`EngineCore.swift:425-442`) empties the pump but leaves `SessionCore.stages`, `plan` and `installedPlan`, whose
`lowered.resolved`, `.switches` and `.results` hold the bindings; the equal-pipeline path (`EngineCore.swift:643-647`)
replaces `session.stages` and the pump's bindings but not `session.plan.lowered`. To resolve: let go of the description
and the plan at detach, and put the new bindings into the running plan's `lowered` on an equal update.
