## Lens checklist (§11.5)

- **A — API, architecture, platform.**
  - **Names and shapes (§4–§8).**
    - GPU-4 names `MedianStrategy.metal`, and §5.3 has "`.metal`, offline (WP-612)". Both exist, with `.selectionNetwork` and `.automatic`, as static members in constrained extensions (`Sources/ZTronDSPAnalysis/Separation/MedianStrategy.swift:223–236`).
    - §6.10 says only that offline `.metal` runs the same network. CR-023 item 16 (Proposed) lists the additions:
      - `DSP.harmonicPercussiveMasks(of:binCount:…)` and `DSP.harmonicPercussive(_:binCount:select:…)`;
      - `MetalMedian` and `AutomaticMedian`;
      - the offline requirement `filter(_:rowCount:kernel:along:crossovers:checkpoint:)`.
    - The API digest passes. `.incrementalSortedLanes` is optional (WP-533, `OPT`) and absent, which WP-R5 allows.
  - **Strategy conformance (§5.3).** The choice is a value passed where the separation is declared (`median: some MedianStrategy = .automatic`).
    - `MedianStrategy` is a public protocol. Its offline job has a default (`MedianStrategy.swift:91–100`) that runs the conformer's own filters, so a conformer written outside the package gets the offline path without writing it.
    - Everything such a conformer needs is public: `MedianFilter`, `MedianAxis`, `Implementation`, `CrossoverTable`, and `BackgroundWork.Checkpoint` (`ZTronDSPCore/Background/BackgroundWork.swift:21`).
    - `AutomaticMedian` composes a `MetalMedian` with the CPU lanes as its fall-back. No Decorator applies: the offline functions are not stages.
  - **DEP-1 and DEP-2.**
    - The files import the Core and Metal targets, Accelerate and Foundation (`MedianStrategy.swift:1–3`, `OfflineSeparation.swift:1–2`). §4.2 lets the analysis target import the Metal target (GPU-4). DEP-1 governs targets, and the gate passes ("the graph equals §4.2"). The "may import" column of §4.2 does not list Foundation for this target, but 44 of its 68 files import it.
    - No MetalKit, no SwiftUI.
    - The kernel lives in `ZTronDSPMetal` (`Compute/MetalMedianFilter.swift`, public) and is wrapped as a strategy (GPU-4).
  - **EXT-1.** No `@_spi`, no `package` access, no `@testable` in these files.
  - **VIS-1.**
    - The strategies are public structs with `let` stored properties.
    - The extension point is a public protocol.
    - `OfflineSeparation` and `MedianOffline` are internal.
    - The test hooks are internal where the table names `package`: A-NB16.
  - **VIS-2.** A-33. **VIS-3.** The digest passes; the CR is named above.
  - **IMM and API-6.**
    - The values are immutable, with no public `var`.
    - Every setting is a labelled argument with a default or a strategy value.
    - `CrossoverTable` is the table of SEL-5, not a configuration object.
  - **§9.2: Sendable, typed errors, background work.**
    - `MedianStrategy: Hashable, Sendable`.
    - The DSP functions return arrays (BG-2).
    - Every throwing member throws `DSPError` (typed): `MedianStrategy.swift:67–69`, `:85–88`, `:92–95`, `:157–159`, `:164–167`, `:197–199`, `:203–206`; `OfflineSeparation.swift:34–38`, `:55–59`.
    - **BG-1.** Both functions are `async`, and their work runs in `BackgroundWork.run` (`OfflineSeparation.swift:39`, `:60`).
    - **BG-3.** The work checks for cancellation:
      - between the two medians (`:100`);
      - every 64 frames inside the medians (`MedianStrategy.swift:251`, `:274`, `:283`);
      - in the masks (`OfflineSeparation.swift:118`).
    - The synchronous `filter` of a strategy blocks. Its requirement says "Background work: it blocks and allocates" (`MedianStrategy.swift:73`). That is what BG-1 asks of an analysis; the row of §5.11.1 for strategies names only the control context, which is where `makeFilter` runs.
  - **PLAT-1.** The build for a deployment target of iOS 15.0 succeeds (minos 15.0), so the compiler admits every API used here.
  - **§8.6 and §9.5.** No UIKit, AppKit, `AnyView` or Combine; lint is clean.
  - **GPU-1.**
    - A live frame is filtered on the CPU by rule (above).
    - Offline, `.automatic` takes the GPU from `CrossoverTable.medianGPU`, counted as kernel × bins × frames (`MedianStrategy.swift:192–195`, one product checked for overflow and one comparison: SEL-4). The shipped value is the initial 2²⁴ (`ZTronDSPCore/Toolkit/Implementation.swift:84`).
    - CR-023 item 1 measured the GPU ahead, end to end, from 4.5·10⁶ values (17 × 513 × 512) on this simulator. On this host, then, the GPU is chosen only where the measurement shows it faster. The values for reference devices await WP-611d (A-NB17).
  - **GPU-2.** Not applicable: there is no render path here.
  - **GPU-3.** The CPU lanes are the parity oracle, bit for bit (above). They are also the fall-back, on `backendUnavailable` and `resourceAllocationFailed` (`MedianStrategy.swift:213–216`). A caller's error and a cancellation are rethrown, not swallowed.
  - **GPU-4.** Without a device, `.automatic` uses the CPU, and a forced `.metal` is `backendUnavailable`, also through the DSP functions.
