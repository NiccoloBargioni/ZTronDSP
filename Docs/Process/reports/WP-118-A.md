## Lens checklist (§11.5)

- **R — real-time safety and performance.** RT-1…RT-9. The allocation audit exists and passes. No hidden copies. Complexity as registered in §7.2. A benchmark is recorded. Setups created when the plan is compiled only. Implementations bound by size (SEL-3).

- RT-2, RT-5: what each type documents for the analysis thread (`append`, `window`, `reset`; `add`, `reset`; `HistoryBuffer.swift:8–9`, `OverlapAdder.swift:13–14`), and `latest`, is pointer arithmetic, `memcpy`, `memmove`, `memset`, `vDSP_vma` and `vDSP_vadd` on `AlignedBuffer` storage owned by a `final class`: no allocation, no lock, no Objective-C message, no logging, no `await`, no dynamic dispatch. RT-3: every buffer is allocated in `init`, which both types put on the control context. `flush(into:)` and `latest` allocate nothing either ([P]), though the threading lines do not name them. Neither type carries the `@_noAllocation @_noLocks` annotations of RT-7 layer 2; their loops call `memcpy` and vDSP, so they are not pure-Swift leaf loops, and layer 3 (the run-time audit) covers them.
- The allocation audit exists, passes in Debug and Release, and fails when either hot path allocates ([M]).
- No hidden copies: `window` and `latest` return pointers into the mirrored storage; each sample is written twice by design, which the type documents (`HistoryBuffer.swift:5–6`); a batch longer than the window copies only its last `count` samples (`:54–58`). `add` shifts the held sums by `frameSize − hopSize` samples with `memmove` on every call: O(frameSize), the same order as its multiply-add. §7.2 registers no complexity for either type. No transform setup is involved; SEL-3 does not apply (one implementation each).
- No benchmark of either type is recorded (A-11). The cost measured here, under load from other agents and not evidence: Release, `append` of 512 samples into 2 048, 57 ns; `add` of 2 048 / 512, 739 ns.
- The tree's overlap-add tolerance (absolute 2·10⁻⁵) is about a hundred times the deviation measured; the row states no tolerance, and this is not lens R's.
