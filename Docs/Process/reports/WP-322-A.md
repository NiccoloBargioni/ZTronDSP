## Lens checklist (§11.5)

- **N — numerical correctness.**

- Definition (REAL-5): the sum of the latencies of the stages upstream. Kernel specs add `latencyFrames / sampleRate` at their position, analysis steps their `latency` in seconds (`LoweringContext.swift:79-104`); a rate changer's frames are counted at the rate in front of it. Frame times are content times (CR-015 item 6): `KernelRun.process` stamps `origin + produced / outputRate − latency` (`PlanStructures.swift:85`).
- Precision: latencies are Double seconds; the test compares for exact equality and passes. A bound switch keeps the latency (ACT-8, tested for a kernel and for a node).
- Edge cases: no stage (0), several stages (sum), a processed source in front (its latency is part of the environment behind it, tested).

## Findings (VER-4)

| # | Checklist item | Location | Evidence | Severity |
|---|---|---|---|---|
| 1 | Acceptance of the row; REAL-5; ENV-4 (latency at a sink); ACT-4 (".bypassed removes the stage") | `Sources/ZTronDSPCore/Compiler/PlanCompiler.swift:101-103` | A stage with latency that is switched off by a constant is compiled away, and its latency stays in the environment: `session.environment.latency` and the environment a sink is claimed with report 37 frames where the impulse is delayed by 0. An update that flips such a constant changes the real latency and reports no `.outputChanged`, because the two reported figures are equal. | blocking |

**Finding 1, to reproduce or resolve.** Probe (fails in Debug and Release):

```swift
var impulse = [Float](repeating: 0, count: 1_000); impulse[0] = 1
let engine = DSPEngine(blockSize: 64)
let sink = CollectingSink<Samples>()
let session = try await engine.attach(Pipeline { TestDelay(37, isActive: false); TestGain(-1) }.emit(to: sink),
                                      to: BufferSource(impulse, sampleRate: 48_000))
let probe = OutputProbe(); engine.core.addProbe(probe, to: session.core)
try session.start(); _ = await session.reaches(.finished)
#expect(probe.samples.firstIndex { abs($0) > 0.5 } == 0)   // passes: the stage is gone
#expect(session.environment.latency == 0)                   // fails: 37 / 48 000
#expect(sink.environment?.latency == 0)                     // fails: 37 / 48 000
```

Cause: `PlanCompiler.walk` lowers a stage as if it were active, which moves the cursor past it, and for `.constant(false)`
(`PlanCompiler.swift:101-103`) drops its steps without putting the cursor back, so the latency (and anything else the stage
added to the environment) stays. To resolve: restore the cursor to `before` for a bypassed stage that keeps the signal.
