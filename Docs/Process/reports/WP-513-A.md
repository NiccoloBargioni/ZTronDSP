## Change requests filed (FIX-4)

**CR-VA-1 — The range of `Float`: results beyond it, and `Double` parameters used in single precision.**

- *What.* NUM-1 forbids NaN and infinity but does not say what a stage or a one-shot function returns when the true result of finite input lies beyond the range of `Float` (for example `1e20 * 1e20`, a true 10⁴⁰). Neither does any section say what happens to a `Double` parameter (a floor, a margin, a power) that the code narrows to `Float`, where it can round to 0 or to ∞.
- *Why.* The code does four different things. `DSP.convolve` returns ∞. The `Autocorrelation` step returns NaN for `.none`, `.biased` and `.unbiased` at ×10²⁰ (112 of 112 values, `VAEdges/e04AutocorrelationStep()`). `.coefficient` returns zeros. Separation parameters above 3.4·10³⁸ or below 1.4·10⁻⁴⁵ change the answer (A-18 in `WP-530-A.md`, A-20 in `WP-531a-A.md`). A caller cannot rely on any of these.
- *Evidence.* `VerifierA/out/edge-e01-convolve.txt`, `edge-e04-autocorrelation-step.txt`, `edge-e09-masks.txt`, `edge-e10-separation-parameters.txt`.
- *Proposed wording* (NUM-1, second sentence): "A value whose true result lies beyond the range of `Float` is returned as ±`Float.greatestFiniteMagnitude`, never as an infinity or NaN. A `Double` parameter that is used in single precision is refused with `invalidParameter` when it lies outside ±`Float.greatestFiniteMagnitude`, or when it is non-zero and rounds to 0 in `Float`."
- *Sections affected.* §6.1 (NUM-1), §6.7, §6.9, §6.10, and §9.3 (what is invalid input).

**CR-VA-2 — Non-finite values given by the caller to one-shot and offline functions.**

- *What.* NUM-1 makes a source adapter replace a non-finite sample by 0. `DSP.convolve`, `DSP.correlate`, `DSP.autocorrelate`, `DSP.harmonicPercussiveMasks`, `DSP.harmonicPercussive` and `MedianOracle` take arrays from the caller with no adapter in between, and nothing says what they do with NaN or ±∞.
- *Why.* The strategies disagree. `.direct` spreads NaN where it reaches. `.fft` spreads it to every value. `.partitioned` throws "Could not allocate a partitioned kernel", which names the wrong cause. `.coefficient` returns zeros. On the GPU, the median of a NaN differs from the CPU's.
- *Evidence.* `out/edge-e01-convolve.txt`, `edge-e02-correlate.txt`, `edge-e03-autocorrelate.txt`, `edge-e12-offline-data.txt`.
- *Proposed wording* (NUM-1, new last sentence): "A one-shot or offline function that is given a non-finite value refuses it with `DSPError.invalidParameter`, naming the input and the index of its first non-finite value; the check precedes any other work."
- *Sections affected.* §6.1 (NUM-1), §6.7, §6.10, §7.4 (the oracle and the GPU parity of GPU-3), §9.3.

**CR-VA-3 — What `.same` returns when the second input is the longer.**

- *What.* §6.7 names the modes without defining `.same`. The oracle table names `numpy.convolve` for WP-513, whose `mode='same'` returns max(N, K) values. The code, its doc and `scipy.signal.convolve` return N values.
- *Why.* For N ≥ K the two libraries agree: N values from index ⌊(K−1)/2⌋ of the full result. For N < K they do not, and the specification does not say which one is the reference.
- *Evidence.* `VerifierA/scripts/numpy_same.py` (`out/numpy-same.txt`): for `[1, 2, 3]` and `[1, 2, …, 7]`, NumPy returns 7 values `[4, 10, 16, 22, 28, 34, 32]` and SciPy 3 `[16, 22, 28]`.
- *Proposed wording* (§6.7, after the code block): "`.same` returns as many values as the first input, from index ⌊(K − 1)/2⌋ of the full result, as `scipy.signal.convolve(x, h, mode='same')` does, also when the second input is the longer." In the oracle table, row WP-513: "`scipy.signal.convolve` (`numpy.convolve` for `.full` and `.valid`)".
- *Sections affected.* §6.7, §12 (the oracle table, rows WP-513 and WP-514).
