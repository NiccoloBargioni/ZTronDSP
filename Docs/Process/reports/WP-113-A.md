| A-28 | §12 acceptance "the implementations agree bit for bit"; SEL-6 ("agree bit for bit … the element-wise ones … Choosing by size never changes what a pipeline computes beyond that"); §7.5 row 24 | `Sources/ZTronDSPCore/Toolkit/Vector.swift:163–171` (native), `:409–413` (vDSP), `:60` (contract) | The native loop computes `value > high ? high : (value < low ? low : value)`. It returns the input when the input equals a bound, so a −0 input against a +0 bound stays −0 (and +0 against −0 stays +0), where `vDSP_vclip` returns the bound's zero; and with low above high it returns low for every input not above high, where `vDSP_vclip` gave high for every input tried. So the automatic `Vector.clip` (and any pipeline that clips) gives different bits for the same input depending on whether the length is below 512 (figures above).
