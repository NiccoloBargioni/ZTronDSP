## Lens checklist (§11.5)

- **N — numerical correctness.**
  - Definition (MAT-3): `%.17g` and `%.9g` round-trip every finite `Double` and `Float` tried, subnormals and the extremes included.
  - Precision: `Float` vectors and matrices are written with 9 digits from the `Float` itself (`0.100000001`), not widened to 17.
  - Edge cases: empty vectors (`[]`), negative zero, NaN and ±∞ in real vectors, `nil` in optional vectors (`NaN`); a complex element with a NaN or infinite imaginary part (B-12); matrix shapes whose product overflows (B-13); empty matrices of a non-zero dimension, reserved words as names, `subplot(0, 0, 0)` and carriage returns in text (B-27).
  - No tolerance: every comparison here is exact.

| B-12 | N — the result against the cited definition: MAT-2 (core MATLAB, "so it also runs in GNU Octave") and MAT-3 ("A value that is undefined … is written as `NaN` … the only place NaN appears") | Sources/ZTronDSPCore/Export/MATLABScript.swift:120-123 | The imaginary part is written as `format(abs(im)) + "i"`, so `vector("z", real: [1, 1, 1], imaginary: [.nan, .infinity, -.infinity])` emits `z = [1+NaNi 1+Infi 1-Infi];`. The suffix `i` makes an imaginary literal of a numeric literal only; `NaN` and `Inf` are functions, so `NaNi` and `Infi` are identifiers and the script stops at an undefined name instead of defining the vector (the real-part cases `NaN+1i`, `Inf+1i`, `-Inf-1i` are valid). `check_dumps.py`: "FAIL matlab: 3 of 8 complex elements are not MATLAB" (Debug and Release); `VerifierBProbes.wp120_aComplexElementWithANonFinitePartIsAMATLABNumber` records an issue in both configurations. Reproduction: `ZTD_DEVICE=ztdsp-27-vm1b Scripts/xc.sh test "ZTronDSPCoreTests/VerifierBProbes/wp120_aComplexElementWithANonFinitePartIsAMATLABNumber()"`, or the final stage and `python3 VerifierB/scripts/check_dumps.py`. Resolution: write an element with a non-finite part as `complex(re, im)` (core MATLAB, also in Octave), and add such an element to the golden script. That `NaNi` is rejected was not run in MATLAB or Octave (neither is installed); it follows from the grammar of both. | Blocking |
| B-13 | N — edge cases; §9.3 "No `fatalError` or `precondition` is reachable from public API through invalid input" | Sources/ZTronDSPCore/Export/MATLABScript.swift:142 | `matrix("m", values: [], rows: Int.max, columns: 2)`: the guard computes `rows * columns`, which overflows, and the process stops before any typed error; the probe `VerifierBCrashProbes.matlabMatrixOverflow` leaves its marker at "started" in Debug and in Release (`.build/vb2/crash-probes-{debug,release}.out`).
