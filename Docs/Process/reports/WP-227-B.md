## Lens checklist (§11.5)

- **R — real-time safety and performance.**
  - `process`, `command` and `reset` are `ZTD_NONBLOCKING`, defined in a target built with function-effect errors (the check bites: `malloc(16)` written into `ztd_gain_process` stops the package build: "function with 'nonblocking' attribute must not call non-'nonblocking' function 'malloc' [-Werror,-Wfunction-effects]"). Read against RT-2: no allocation, no lock, no system call, no logging; every loop is bounded by the frames, the channels or a size fixed at creation.
  - Allocation audit: `SubsampleKernelTests.processingIsAllocationFree` (both kernels, 1 000 blocks each of 509 and 512 frames, resets) passes in Debug and Release. It bites: with an allocation the compiler cannot see (a call, from the hot function, to a helper in another file that does `malloc` and `free` and is declared `nonblocking`, as an allow-list entry is; tried in Debug and in Release, with the same counts) in `ztd_subsample_process` and `ztd_zero_stuff_process` it reports 2 000 allocations.
  - One small state block each, allocated at creation; no setup; no buffer; no copy beyond the output itself. The phase is one integer carried across blocks.
  - Cost O(frames / M) and O(frames · L). Benchmark recorded: `kernel.subsample.by-3.512` 88 ns, `kernel.zero-stuff.by-3.512` 244 ns.
