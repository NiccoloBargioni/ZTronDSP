## Lens checklist (§11.5)

- **R — real-time safety and performance.**
  - RT-2: a `SampleProcessor` runs behind the kernel ABI (`ProcessorKernel`): per block one copy of the input into the kernel's output, one call through the existential, no allocation, no lock. A C kernel of the caller's is called directly by the plan. Audits: `ExecutionTests/aPlanWithKernelsNodesBranchesAndSinksRunsWithoutAllocating` holds one of each; the verifier's `vb339_stagesOutsideTheCoreAllocateNothing` adds a bound switch on the processor and flips it (4 × 1 000 blocks: 0 allocations).
  - RT-3: the processor and the C kernel's state are made on the control context when the plan is compiled and released through the kernel's `destroy` off the analysis thread.
  - No hidden copies beyond the one that turns "in → out" into "in place"; it is stated at the call. Cost (Release, indicative): a processor that does nothing 112 ns per block of 512 frames, an identity kernel of the caller's 107 ns.
  - Bound by size (SEL-3): the stage's `make` receives the channel count, the rate and the largest block.
  - Fusion: a custom kernel or processor is a barrier (EXT-2); `fusedAndUnfusedGainsAgreeBitForBit` uses one as such.
  - A benchmark is recorded: none in this package (EXT-4's 5 % is WP-907's).
