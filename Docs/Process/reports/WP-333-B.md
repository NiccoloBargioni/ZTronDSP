## Lens checklist (§11.5)

- **V — visual stability and rendering.** A feed has no renderer; the lens is applied to what §8.3 and §8.4 ask of a feed.
  - V-2: nothing in a feed is observable. A view polls `generation`, one atomic load; it moves by exactly one per column and on a clear, a trim or a new shape, and does not move otherwise (two engine turns without data: unchanged; verifier). "No new data for one second: 0 draws; each tick returns after one atomic load" is therefore within reach of a view.
  - V-5: `read` copies only the columns that arrived since the cursor, oldest first, with the position of the first, so an upload is proportional to what is new; a reader at half the data rate gets every column (no skip until it lags by more than the history).
  - V-6: `FeedRead.isReset` is true for a new shape, a trim and a clear, and false for a re-attachment to the same shape and for stop and start (verifier): a texture is reallocated only when `rowCount` or `history` changed.
  - ACT-11 / §8.3: liveness is decided on the control context and the main thread (`LivenessBoard`); the analysis thread never calls `setLive`. `onLivenessChange` runs its handler on the main actor, once per change, and is not told about frames.
  - Dirty-set causes, draw and upload counters, animation, pinch, size transitions, golden images: not applicable to this package.
