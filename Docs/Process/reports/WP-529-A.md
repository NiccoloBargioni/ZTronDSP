## Lens checklist (§11.5)

- **N — numerical correctness.**
  - Definition: the median of an odd number of values (1…255), the line reflected at its ends with the edge value repeated (§6.1, SciPy's `reflect`); along time, the running median of the last `kernel` frames is the centred one half a kernel late. The lanes are the odd-even-merge network pruned to the median (register row 16). Read against `MedianKernels.swift` and `MedianOracle.swift`.
  - Precision: a median selects, it does not compute: bit-for-bit equality with the oracle is the right criterion, and the tests use it.
  - Tolerance: exact equality; nothing loosened.
  - Currency: the first lines of `median-lanes.md` and row 16 of `currency-2026-11.md`: current.
  - Edge cases (`out/edge-e08-medians.txt`; lanes against the oracle, kernels 1, 3, 5 and 255, along time and along frequency, 58 comparisons):

    | Input | Result |
    |---|---|
    | Empty (`filter([], rowCount: 3, kernel: 3)`) | `[]` |
    | One bin, one frame; one bin, 4 frames | Equal bit for bit |
    | Ties | Equal bit for bit |
    | Signed zeros | Equal bit for bit (the same zero is chosen) |
    | `±∞` | Equal bit for bit |
    | Subnormals | Equal bit for bit (kept, not flushed: a median does no arithmetic) |
    | `FLT_MAX` | Equal bit for bit |
    | `NaN` from the caller | The lanes and the oracle differ (5 or 6 NaN of 9 against 0 or 1). The documentation leaves it unspecified: CR-VA-2 |
    | DC, Nyquist, silence, full scale | Covered by the stress test (`theMedianLanesOfEveryStressSignalAreTheSortedMiddle`) and by the reference above; a median of a constant is the constant |
    | `rowCount`, `kernel` Int.max, Int.min, 0, −1, an even kernel (lanes) | `invalidParameter` ("a median is taken over an odd number of values from 1 to 255", "a lane holds between 1 and 2²⁴ values", "do not fill frames of …") |
    | `MedianOracle.median([])` | NaN, as its documentation says (A-NB5) |
