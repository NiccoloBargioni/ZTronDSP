## Lens checklist (§11.5)

- **R — real-time safety and performance.**
  - `process`, `command` and `reset` are `ZTD_NONBLOCKING`, defined in a target built with function-effect errors (the check bites: `malloc(16)` written into `ztd_gain_process` stops the package build: "function with 'nonblocking' attribute must not call non-'nonblocking' function 'malloc' [-Werror,-Wfunction-effects]"). Read against RT-2: no allocation, no lock, no system call, no logging; every loop is bounded by the frames, the channels or a size fixed at creation.
  - Allocation audit: `DecimatorKernelTests.processingIsAllocationFree` (1 000 blocks of 37, 512 and 48 frames, a reset) passes in Debug and Release. It bites: with an allocation the compiler cannot see (a call, from the hot function, to a helper in another file that does `malloc` and `free` and is declared `nonblocking`, as an allow-list entry is; tried in Debug and in Release, with the same counts) in `ztd_decimator_process` it reports 1 000 allocations.
  - Everything is allocated in `ztd_decimator_create`; `vDSP_desamp` needs no setup and is on the allow-list.
  - Cost: K multiplications per output sample for blocks that are whole cells (16 outputs). Benchmark recorded: `kernel.decimator.by-2.512` 1399 ns, `.by-4.512` 1301 ns.
