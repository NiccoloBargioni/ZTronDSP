## Lens checklist (§11.5)

- **R — real-time safety and performance.**
  - `process`, `command` and `reset` are `ZTD_NONBLOCKING`, defined in a target built with function-effect errors (the check bites: `malloc(16)` written into `ztd_gain_process` stops the package build: "function with 'nonblocking' attribute must not call non-'nonblocking' function 'malloc' [-Werror,-Wfunction-effects]"). Read against RT-2: no allocation, no lock, no system call, no logging; every loop is bounded by the frames, the channels or a size fixed at creation.
  - Allocation audit: `processingUpdatesAndResetsAreAllocationFree` (1 000 blocks, loud and silent ones so that the state reset of the hygiene rule runs, 50 updates) passes in Debug and Release. It bites: with an allocation the compiler cannot see (a call, from the hot function, to a helper in another file that does `malloc` and `free` and is declared `nonblocking`, as an allow-list entry is; tried in Debug and in Release, with the same counts) in `ztd_biquadm_process` and `ztd_biquadm_command` it reports 1 050 allocations.
  - One setup for all channels, created in `ztd_biquadm_create` (`vDSP_biquadm_CreateSetup`; the expanded coefficient table is allocated and freed there), destroyed in `destroy`. `vDSP_biquadm`, its setter and `vDSP_biquadm_ResetState` are on the allow-list.
  - Per block, besides the filter: a scan of at most 2·sections + 2 trailing frames per channel for the quiet-run rule (ztd_biquad.c:216-234). No copy of the signal.
  - Benchmark recorded: `kernel.biquadm.4-sections.2-channels.512` 3470 ns (after an update 3469 ns), `.8-channels.512` 11244 ns; the mono-setup kernel on the same work: 3925 and 15640 ns.
