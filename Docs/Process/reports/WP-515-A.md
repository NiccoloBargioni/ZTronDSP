## Change requests filed (FIX-4)

**CR-VA-4 — How VIS-2 applies to protocol witnesses and to unavailable diagnostic overloads.**

- *What.* VIS-2 asks every public symbol to be documented with its threading contract. It does not say whether this holds for a member that only satisfies a protocol requirement (`stageDescription`, `lower(_:)`, `typealias Input`, `makeTransform`, `makeFilter`, `mask`, `validate`), whose contract is the requirement's. Nor does it say whether it holds for an overload marked `@available(*, unavailable, message:)`, which exists only to carry an ORD-4 sentence and can never be called.
- *Why.* The batch has 57 public declarations without a `///` comment. Nine of them are unavailable `buildPartialBlock` overloads in `Order/OrderDiagnostics+Correlation.swift`, `+Rhythm.swift` and `+Separation.swift`, and most of the others are witnesses. Applied as written, VIS-2 makes each of them blocking. For an overload that cannot be called, a threading contract has no meaning.
- *Evidence.* `VerifierA/out/vis2-scan.txt`, `out/vis2-contract.txt`.
- *Proposed wording* (VIS-2): "Every public symbol is documented with its threading contract: which context may call it, and whether it may allocate. A statement on a type covers its members. A member that only satisfies a protocol requirement has the contract of the requirement, which the protocol documents. A declaration marked `@available(*, unavailable)` carries its message and needs no contract."
- *Sections affected.* §5.11 (VIS-2), §11.5 (lens A, "Public API documented with its threading contract").
