## Change requests filed (FIX-4)

Two, for the backlog items BL-1 and BL-3, where this verifier finds the text of the specification wrong or ambiguous. Neither holds the package; finding 3 is the implementation's to resolve, by the code or by a change request of its own.

### CR (proposed): §6.10, the floor of the masks is a floor of the medians (BL-1)

- **What.** §6.10 says "Where the denominator is below the floor both masks are 0 (NUM-1)". The implementation gives a mask of 0 where neither median reaches the floor: `!(own >= floor || other >= floor)` in `SoftMask.mask` (`MaskStrategy.swift:92`), `own >= floor` in `HardMask.mask` (`:116`), the competitor's median already multiplied by its margin; and, with a floor of 0 and a soft mask, it shares a bin whose medians are both 0 equally (`:94-97`, documented at `Steps/HarmonicPercussive.swift:21-23`). CR-023 item 12 describes the implementation's rule and calls it "as §6.10 says". The two rules differ, in both directions.
- **Why.** The denominator `Hᵖ + (m·P)ᵖ` is a median to the power p; the floor is a median ("The least median that counts as a value", `HarmonicPercussive.swift:64`). Read word for word, a clear harmonic median of 10⁻⁶ against a percussive median of 0, under p = 2 and the default floor of 10⁻¹⁰, has a denominator of 10⁻¹² and would go to the residual. The implementation's reading is the useful one; the specification should say it, and CR-023 should not present it as the present text.
- **Evidence.** `vb530FloorRuleAgainstTheLiteralDenominator` (`VerifierB/probe-results/`): H = 10⁻⁶, P = 0, p = 2, floor 10⁻¹⁰: harmonic mask 1, where the words of §6.10 give 0; H = 10⁻⁵: 1 (the words: 0); H = 10⁻⁴: 1 (the words: 1); H = P = 6·10⁻¹¹ everywhere, p = 1: masks 0 and 0, where H + P = 1.2·10⁻¹⁰ lies above the floor and the words give 0.5 and 0.5. `SeparationMaskTests.whereNeitherMedianReachesTheFloorBothMasksAreZero` holds the implementation's rule.
- **Proposed wording** (§6.10, the second bullet, its last sentence): "Where neither median reaches the floor — `H` and `m_H·P` for `M_H`, `P` and `m_P·H` for `M_P` — the mask is 0 (NUM-1), and the bin goes to the residual; with a floor of 0, a soft mask shares a bin whose medians are both 0 equally." CR-023 item 12 then reads "… are both 0, as §6.10 says after CR-xxx".
- **Sections affected.** §6.10; CR-023 item 12.

### CR (proposed): RT-2, dynamic dispatch in a node that runs per frame (BL-3)

- **What.** RT-2 allows dynamic dispatch "once per kernel or node per block, never inside a per-sample loop". A node of the analysis thread that follows a framing step is called once per frame, and the nodes of this batch call the strategies' objects through existentials once per frame each: `HarmonicPercussiveNode.process` (`HarmonicPercussiveNode.swift:135`) calls two `any MedianFilter` (`:154`, `:173`) and, through `SeparationMasks`, `any MaskStrategy` once, twice for the residual (`:34`, `:41`, `:56-57`); `TempogramNode.process` calls `any TempogramTransform` once per value of the curve (`TempogramNodes.swift:72`), and the Fourier transform calls `any FFTPlan` (`:202`). A block of 512 samples at a hop of 128 holds four frames: four calls of the node and of each of these, more than "once per node per block" read word for word.
- **Why.** The core has called frame nodes once per frame since M3, and the extra calls are per frame, never inside a loop over samples or bins: their cost does not grow with the frame. The text should say what a frame node may do, so that verifiers apply it the same way.
- **Evidence.** The lines above; the nodes' allocation audits pass (`HarmonicPercussiveTests.theNodeRunsWithoutAllocating`, `TempogramTests.theNodesRunWithoutAllocating`, `MedianKernelTests.theKernelsRunWithoutAllocating`), and the stock full analysis allocates nothing over 10 000 blocks (`FullAnalysisAuditTests`, Debug and Release).
- **Proposed wording** (RT-2, second sentence): "Dynamic dispatch is allowed once per kernel or node per block, and in a node that runs per frame once per frame, for the node and for each strategy object it holds; never inside a per-sample or per-bin loop."
- **Sections affected.** §5.6 (RT-2).
