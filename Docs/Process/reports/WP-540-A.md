## Lens checklist (§11.5)

- **A — API, architecture, platform.**

- Names and shapes, against §6.14 and the digests (`api-digest.sh`, 10 digests equal):
  - `FeedSnapshot`, `InversionReport` and `ScalarTrack` conform to the public `MATLABExportable` (MAT-1), with `matlabScript() async throws(DSPError) -> String`, the shape of §6.14's example;
  - `ScalarTrack`, the "track of `ScalarFrame`s" of the table, is a public type that §6.14 does not name, and CR-019 item 15 lists it. One initialiser cuts the longer of its two arrays to the shorter; the other spaces the frames at a rate;
  - the must-compile front-end fixture calls the exports from outside the package (`Tests/CompileFixtures/valid/OrderRulesOfTheSpectralFrontEnd.swift:125–126`; `compile-fixtures.sh`).
- MAT-2 to MAT-5:
  - the commands are those of MAT-2, written through the core's `MATLABScript` (WP-120);
  - numbers go through `MATLABScript.format` (`%.17g`, `%.9g`). `String(format:)` writes them without a locale, so the decimal mark is always a point;
  - nothing in a script depends on the date, the machine or the snapshot's environment;
  - the package writes no file (MAT-5). `FrameExports.swift` imports Foundation and the core only, and returns a `String`.
- Concurrency and background (§9.2):
  - BG-1, as above;
  - BG-2: the result is a `String`;
  - BG-3: the work is checked before and after it runs.
  - The values captured into the closure are immutable and `Sendable`.
- Immutability, and no configuration object: `ScalarTrack` holds two `let` arrays, and `MATLABScript` returns a new value from every call.
- DEP: the conformance of the core's `FeedSnapshot` to the core's protocol is declared in the analysis target, beside the other exports, within one package. `check-dependency-graph.sh` equals §4.2.
- Typed errors: `throws(DSPError)` throughout. But a snapshot whose values do not fill it ends the process instead of throwing (A-15).
- No Combine, no `AnyView`, no UIKit (`lint-bans.sh` clean). Availability: nothing beyond iOS 15.
- VIS-2: see A-9.

What the evidence for A-15 shows:

1. **Run.** The public initialiser accepts `FeedSnapshot(content: .heatmap, axis: nil, environment: nil, rowCount: 3, values: [1, 2], times: [0])`. Its `matlabScript()` ends the test process: `Swift/ContiguousArrayBuffer.swift:695: Fatal error: Index out of range`, then "Restarting after unexpected exit, crash, or test timeout" (`.build/vlogs/probe-run6.log`). §9.3 asks for a typed error, for example `invalidParameter`.
2. **The cause.** The transposition reads `values[column * rows + row]` for every row and column the snapshot claims (`:51–52`). It never checks that `values` holds `rowCount × times.count` values. The initialiser's comment asks for that layout but does not check it (`FeedSnapshot.swift:30–31`). Read, not run: `rows * columns` (`:50`) is unchecked arithmetic too, and overflows for a `rowCount` near `Int.max`.
3. **The same gap without a trap.** A waveform snapshot of 3 values for 2 pairs exports a script whose `minima` holds 2 values and whose `maxima` holds 1. `plot(times, maxima)` is then a statement MATLAB refuses, because the vectors differ in length. Evidence: probe `dumpExports`, `VerifierA/out/scripts/uneven-waveform.m`; `check_matlab.py` refuses it.
4. **The sibling types do check.** `ScalarTrack.init(_:times:)` and `InversionRoundTrip.init` cut the longer array to the shorter (`FrameExports.swift:102–106`, `Sources/ZTronDSPAnalysis/Inversion/InversionReport.swift:58–63`).

Reproduction, as in `VerifierA/README.md` §1:

```
cp VerifierA/probes/VerifierAProbeTests.swift Tests/ZTronDSPAnalysisTests/
TEST_RUNNER_VA_CRASH=1 ZTD_DEVICE=ztdsp-27-vm5aa Scripts/xc.sh test "ZTronDSPAnalysisTests/VerifierAProbes/findingAHeatMapSnapshotWhoseValuesDoNotFillItEndsTheProcess()"
rm Tests/ZTronDSPAnalysisTests/VerifierAProbeTests.swift
ZTD_DEVICE=ztdsp-27-vm5aa Scripts/xc.sh build
```

The test is listed among the failing tests, after the crash. The waveform case needs no build: `cd VerifierA/python && python3 -B check_matlab.py` prints "export uneven-waveform: refused".

Resolution of A-15:

- At the top of `FeedSnapshot.script()`, refuse a snapshot whose values do not fill it with `DSPError.invalidParameter`:
  - for a heat map, `values.count == rowCount × columnCount`, multiplied with an overflow check;
  - for a waveform, also `rowCount == 2`.
- Check the size of MAT-4 at the same place, before the copy (A-10).
- Or make the initialiser cut what does not fill a column, as `ScalarTrack` does, and say so in its comment. That code is WP-341's.
- Add an uneven heat map and an uneven waveform to `ExportTests`.
